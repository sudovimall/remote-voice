# Per-Member Listening Controls 设计文档

日期：2026-05-22

## 目标

为房间成员增加当前听众视角下的接收控制：

- 当前成员可以在成员列表中选择“不听”某个其他成员。
- 被屏蔽成员的语音不再下发给当前听众。
- 当前成员可以随时重新选择“接收”该成员语音。
- 不听名单在刷新并恢复同一成员身份后保留。
- 显式离开或以新成员身份重新加入房间后，不继承旧的不听名单。

## 范围

### 本阶段做

- 在成员列表的其他成员行增加当前听众私有的“不听”或“接收”切换按钮。
- 扩展 WebSocket 控制协议，允许当前听众修改自己对目标成员的接收策略。
- 在房间状态中保存成员自己的不听名单，使 `resume_room` 能恢复该名单。
- 给当前听众返回可渲染的私有接收状态，不把听众名单广播为公共成员状态。
- 让 SFU fanout、晚加入补挂已有音轨和重新接收已有发布者音轨都遵守监听策略。
- 停止接收时解除当前听众已经挂上的目标发布者下行音轨。
- 增加前端模块测试、WebSocket 测试、房间领域测试和媒体层测试。

### 本阶段不做

- 不提供音量调节、全局静音别人、黑名单管理页或跨成员身份持久化。
- 不让其他成员看到谁屏蔽了谁。
- 不改变发布者的本地静音、房主禁言和公共成员快照语义。
- 不把“不听”实现成浏览器只静音播放器但仍继续接收媒体包。

## 方案选择

### 采用：SFU 按听众维护接收策略

当前听众通过 WebSocket 控制自己的监听策略。服务端把策略挂在当前房间成员身份上，媒体层只给允许接收的听众挂发布者下行音轨。

这个方案符合“不接收该用户语音”的语义，刷新后的恢复也能沿用现有 `resume_room` 身份边界。前端只渲染当前听众可见的私有状态，不需要猜测远端 stream 与成员之间的映射。

### 未采用：浏览器本地屏蔽播放

当前 `MediaSession` 按远端 stream 创建隐藏 `<audio>` 节点，前端没有稳定暴露发布者成员映射。即便补上映射，音频仍然会从 SFU 下发到浏览器，不满足停止接收的要求。

### 未采用：只用前端存储不听名单

`sessionStorage` 可以表达刷新范围，但服务端 fanout 不知道听众策略，媒体层仍要继续下发音轨。把策略放在前端还会让重新协商和成员恢复的行为分散在浏览器侧。

## 状态模型

不听策略是听众私有状态，按以下关系保存：

- 房间：`room_id`
- 听众：`listener_member_id`
- 发布者：`publisher_member_id`

每个房间成员持有自己的不听成员集合。集合只允许引用同房间的其他成员：

- 当前成员不能屏蔽自己。
- 目标成员离开房间并被清理后，其他成员名单中对它的引用一并删除。
- 成员在断线恢复宽限期内仍属于房间时，名单继续有效。
- `resume_room` 恢复同一个成员 ID 时保留该成员名单。
- 显式离开或新加入得到新的成员身份时，不继承旧名单。

公共 `Room` 快照继续描述房间成员、发言权限、静音和连接状态。当前听众的接收策略通过只发给当前连接的私有状态返回，不广播给其他房间成员。

## 协议

### 客户端控制消息

新增控制消息：

- `set_member_listening`
  - `member_id`：目标发布者成员 ID。
  - `listening`：`false` 表示不听，`true` 表示恢复接收。

该控制只允许连接中的房间成员修改自己的接收策略。服务端根据当前 WebSocket 已加入的成员身份确定听众，不接受客户端指定 `listener_member_id`。

### 服务端私有状态消息

服务端给当前听众返回已确认的私有监听状态，至少包含当前被屏蔽的成员 ID 集合。该消息用于：

- 成功加入房间后的首次渲染。
- 刷新后 `resume_room` 的恢复渲染。
- 当前听众切换某个目标成员后的按钮刷新。

公共成员变更事件不携带其他听众名单。普通成员加入、离开、断线和权限变化仍走现有房间快照事件。

## UI 行为

成员列表继续由 `room.js` 渲染：

- 当前成员自己的行不显示监听切换按钮。
- 其他成员的行都显示切换按钮。
- 当前听众正在接收该成员时，按钮文案是“不听”。
- 当前听众已经屏蔽该成员时，按钮文案是“接收”。
- 该按钮不改变目标成员的“可发言”“已静音”“已禁言”等公共状态标签。
- 房主权限按钮保持现有逻辑；监听按钮对普通成员和房主都可用。

`room-controls.mjs` 承担 DOM 无关的信令构造、按钮文案和当前听众监听状态判断。`room.js` 负责把服务端私有监听状态与成员快照组合渲染。

## 媒体数据流

### 发布者出现新音轨

当 SFU 收到某个发布者的新上行音轨：

1. 媒体层读取当前房间内各听众对该发布者的接收策略。
2. 只给允许接收且不是发布者本人的会话挂下行 track。
3. 对挂入了新下行 track 的听众沿用现有重新协商通知路径。

### 听众加入或恢复媒体会话

当听众晚加入，或刷新恢复后建立新的媒体会话：

1. 媒体层收集房间里已有发布者音轨。
2. 跳过该听众当前不听名单中的发布者。
3. 为其余音轨补挂下行 track。

### 停止接收

当当前听众把某个发布者切换为“不听”：

1. 房间领域层先确认并保存私有监听策略。
2. 媒体层解除该听众现有下行集合中属于该发布者的 track。
3. 浏览器继续保留当前房间媒体会话，按需要通过现有重新协商机制收敛下行集合。

解除动作只影响该听众，不影响发布者上行、其他听众下行和房主禁言状态。

### 恢复接收

当当前听众把某个发布者切换为“接收”：

1. 房间领域层移除该发布者的不听策略。
2. 若发布者当前已有上行音轨，媒体层立即把这些音轨挂回该听众。
3. 若挂入了新下行 track，媒体层通过现有重新协商事件通知该听众。
4. 若发布者当前没有上行音轨，只保存策略；后续新音轨按正常 fanout 挂入。

## 错误处理

- 未加入房间的 WebSocket 发出监听控制时返回已有控制错误语义，不修改任何状态。
- 目标成员不存在时返回成员错误，不修改听众名单。
- 目标成员就是当前听众时返回非法控制错误，不写入名单。
- 前端只有在收到服务端已确认的私有监听状态后刷新按钮状态；控制失败时保留上一次已确认状态并展示错误。
- 媒体层恢复接收时如果目标当前没有音轨，不把它视为错误。
- 下行解绑或补挂失败时保留房间控制状态，并通过现有错误路径暴露媒体失败，便于测试和联调定位。

## 模块边界

- `src/domain/room.rs`
  - 保存、校验和清理成员私有不听名单。
- `src/media/mod.rs`
  - 保存媒体层听众策略或读取同步后的策略，控制下行 fanout、解绑和恢复挂载。
- `src/transport/http/signaling.rs`
  - 扩展 WebSocket 控制协议，返回当前连接的私有监听状态，并协调房间状态与媒体状态更新。
- `static/room-controls.mjs`
  - 增加监听控制消息和按钮文案逻辑。
- `static/room.js`
  - 组合公共成员快照与当前听众私有监听状态，渲染成员按钮。
- `static/styles.css`
  - 让成员行新增控制在桌面和窄屏布局下保持可读。

## 测试

### Rust 房间领域测试

覆盖：

- 成员可以屏蔽和恢复接收另一个同房间成员。
- 成员不能屏蔽自己。
- `resume_room` 保留同一成员的不听名单。
- 目标成员离开或过期清理后，相关不听引用被清理。

### Rust 媒体测试

覆盖：

- 发布者 fanout 新音轨时跳过已屏蔽该发布者的听众。
- 晚加入或恢复媒体会话时补挂已有音轨会跳过屏蔽发布者。
- 切换为“不听”会解除该听众已有的目标发布者下行 track。
- 切换为“接收”会给当前已有发布者音轨重新挂下行 track。

### WebSocket 测试

覆盖：

- `set_member_listening` 消息解析和已加入房间校验。
- 非法目标成员和屏蔽自己时返回错误。
- 加入、恢复和切换后当前连接能收到私有监听状态。
- 私有状态不会作为公共房间广播暴露给其他成员。

### Node 前端测试

覆盖：

- 监听控制消息构造。
- “不听”和“接收”按钮文案。
- 当前成员自身不提供监听切换。

### 浏览器联调

覆盖：

1. A 与 B 进入同一房间。
2. A 在 B 的成员行点击“不听”，按钮切换为“接收”。
3. A 刷新并恢复原成员身份后，B 仍显示为“接收”。
4. A 显式离开并重新以新成员身份加入后，不继承旧的不听状态。
5. 桌面和窄屏布局下成员控制不重叠，控制台无相关错误。
