# Browser Page Skeleton 设计文档

日期：2026-05-21

## 目标

为 Remote Voice 增加浏览器客户端的页面骨架，先把大厅页和房间页拆开，让后续 WebSocket、麦克风权限和 WebRTC 音频会话可以按页面边界逐步接入。

本阶段只做可访问、可扩展的前端骨架，不提前实现真实房间加入和音频链路。

## 范围

### 本阶段做

- 增加独立大厅页和房间页。
- 增加共享样式，覆盖桌面和窄屏布局。
- 增加大厅页与房间页的轻量 JS 骨架。
- 增加 Rust 静态文件路由：
  - `/` 返回大厅页。
  - `/rooms/:room_id` 返回房间页。
  - `/assets/...` 返回 CSS 和 JS 静态资源。
- 为大厅页和房间页预留后续状态容器：
  - 表单校验与错误提示。
  - 房间加载、连接异常、麦克风权限提示。
  - 成员列表、房主权限控件、本地语音控制区。
- 增加 HTTP 路由测试，验证页面和静态资源可以访问。

### 本阶段不做

- 不实现创建房间和加入房间 API 调用。
- 不建立 WebSocket 连接。
- 不请求麦克风权限。
- 不创建 `RTCPeerConnection`。
- 不播放或发送真实音频。
- 不引入前端框架或独立打包构建链。

## 页面边界

### 大厅页

大厅页只负责进入语音房间，不承担音频状态。

页面包含：

- 产品名与页面上下文。
- 昵称输入。
- 创建房间入口。
- 房间号输入与加入入口。
- 表单错误提示区和后续流程状态区。

大厅页后续接真实接口时，只负责获取房间页需要的身份和路由信息，然后导航到目标房间页。

### 房间页

房间页是唯一音频工作区。一个房间页实例只对应 URL 中的一个 `room_id`，后续媒体客户端也只维护这一房间的一套 WebSocket 和 WebRTC 会话。

页面包含：

- 房间号与连接状态区。
- 离开按钮。
- 成员列表骨架。
- 成员角色、静音状态、发言权限状态位。
- 房主权限控件占位。
- 本地麦克风控制区占位。
- 设备状态、权限提示和连接错误提示区。

“同一用户同一时间只能进入一个房间接收音频”在页面侧先通过房间页边界表达：页面不会在同一工作区内并列维护多个房间的成员和音频控制状态。

## 视觉方向

前端采用安静、清晰、工具型的语音控制台方向。

- 首屏直接展示真实操作区，不做营销落地页。
- 颜色以中性色和明确状态强调色为主，避免单一紫蓝渐变主题。
- 布局优先支持快速扫描房间号、成员状态和语音控制。
- 不堆叠装饰卡片，不在页面里加入解释功能的长文案。
- 控件尺寸稳定，移动端改为上下布局，避免房间控制区与成员区互相挤压。

## 文件边界

- `static/index.html`：大厅页结构。
- `static/room.html`：房间页结构。
- `static/styles.css`：共享样式、状态样式和响应式布局。
- `static/lobby.js`：大厅页骨架交互和输入校验占位。
- `static/room.js`：读取 URL 房间号并初始化房间页骨架状态。
- `src/transport/http/mod.rs`：接入页面与静态资源路由。
- HTTP 测试放在现有 HTTP 路由测试模块附近，验证骨架资源可访问。

## 交互骨架

### 大厅页

- 昵称输入为空时，创建和加入入口展示局部错误。
- 加入入口对房间号做最小格式整理，避免页面在骨架阶段就依赖后端状态。
- 页面跳转行为在接真实 API 前保持明确占位，不伪造已经加入成功的状态。

### 房间页

- 页面从 `/rooms/:room_id` 的路径读取并显示房间号。
- 成员列表使用少量骨架行展示未来状态密度。
- 房主管理区用禁用或占位控件表达后续可接权限状态。
- 麦克风控制区先展示未连接状态，不主动请求权限。

## 错误处理

骨架阶段优先稳定布局和错误容器：

- 大厅页表单错误显示在操作区内，不改变页面主要布局。
- 房间页连接异常与麦克风权限提示保留固定区域。
- JS 无法从 URL 解析房间号时，房间页展示本地错误态。

后续接真实后端后，这些容器承接 API、WebSocket 和媒体层错误，不把错误文案散落在页面结构中。

## 测试

自动化测试覆盖：

- `GET /` 返回大厅页。
- `GET /rooms/ABC123` 返回房间页。
- `GET /assets/styles.css` 可访问。
- 关键 JS 资源路径可访问。

人工浏览器检查覆盖：

- 大厅页桌面布局。
- 房间页桌面布局。
- 大厅页与房间页窄屏布局。
- 房间页房间号状态可从 URL 呈现。

## 后续接入顺序

1. 大厅页接创建房间和加入房间 API。
2. 房间页接 WebSocket 加入、成员状态同步和权限事件。
3. 房间页请求麦克风权限，建立到后端的 WebRTC 会话。
4. 加入房主权限控制、本地静音和真实异常恢复流程。
